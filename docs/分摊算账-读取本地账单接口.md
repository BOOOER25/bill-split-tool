# 分摊算账 · 读取本地账单：getLocalBills

分摊算账 H5 与 Android、iOS 的统一接入约定。此接口是**需要客户端新增的 JSBridge 行为**，不是 HTTP 接口；两份参考文档均未列出现有读取账单能力。

## 读取规则

- 从**当前用户在客户端本地可访问的所有账本**读取，禁止为了本次调用请求业务服务器或触发同步。
- 所有账本的支出**合并后统一排序、总共取最近 200 条**，不是每个账本各取 200 条；不足 200 条返回实际数量，无记录返回空数组。无需选择账本，不受当前打开的账本影响。
- “最近”按消费发生时间倒序，不按导入时间、修改时间。发生时间相同时按稳定的账本 ID、记录 ID 排序，保证顺序可重复。
- 先跨所有账本按支出及有效状态筛选，再统一排序并取 200 条。排除收入、转账、已删除或已作废记录；金额为正整数分。
- 退款记录不单独作为支出返回。原支出暂按本地保存的原金额返回，本版不自动冲抵退款，避免未约定的计算方式。
- H5 固定请求 `scope: "all"`、`limit: 200`、`type: "expense"`。不传当前账本 ID、日期或游标，不分页追加，不返回全量账单让 H5 截取。
- 用户点击“新建分摊”时读取一次；只读，不修改记账数据。用户确认后，H5 将所选消费保存为分摊快照，后续原账单变动不自动修改已创建的分摊单。

## H5 请求

两个平台都传 **JSON 字符串**：

```json
{
  "action": "getLocalBills",
  "requestId": "bill-1",
  "data": {
    "scope": "all",
    "limit": 200,
    "type": "expense"
  }
}
```

客户端须校验请求参数，仅支持上述固定值；不合法时回调失败。

## 成功返回

通过 `window.onSuccessCallback(jsonString)` 回传。必须原样带回请求的 `action` 和 `requestId`：

```json
{
  "action": "getLocalBills",
  "requestId": "bill-1",
  "data": {
    "items": [
      {
        "id": "local-bill-1024",
        "bookId": "local-book-001",
        "bookName": "日常账本",
        "name": "周末晚餐",
        "amount": 36000,
        "date": "2026-11-25",
        "category": "餐饮",
        "icon": "food"
      },
      {
        "id": "local-bill-1023",
        "bookId": "local-book-002",
        "bookName": "旅行账本",
        "name": "打车",
        "amount": 2800,
        "date": "2026-11-24",
        "category": "交通",
        "icon": "car"
      }
    ]
  }
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `items` | array | 所有账本合并后的 0～200 条，已在客户端统一排好序 |
| `items[].id` | string | 稳定、非空的本地消费 ID，与 `bookId` 组合唯一 |
| `items[].bookId` | string | 每条消费所属账本的稳定本地标识，非空；不传账号、token 等信息 |
| `items[].bookName` | string | 每条消费所属账本的名称，非空，用于页面及导出展示来源 |
| `name` | string | 展示名称；备注为空时由客户端用分类名称兜底 |
| `amount` | integer | 正整数，单位**分**；36000 表示 ¥360.00，不能传元或格式化金额 |
| `date` | string | 本地账本时区的消费日期，`YYYY-MM-DD`；排序在客户端按完整发生时间完成 |
| `category` | string | 分类展示名；没有分类时传“其他” |
| `icon` | string | 可选：`home` / `food` / `car` / `coffee` / `receipt`；未知值展示通用图标 |

所有账本均无支出或没有可访问账本也是成功，返回 `"items": []`。不要求用户先打开某个账本，不能用空数组掩盖数据库错误。

页面保留 `sourceId`、`bookId`、`bookName`。内部明细 ID 使用 `bill:` 加分别 URI 编码的账本 ID、消费 ID 组合，允许不同账本出现相同消费 ID，但拒绝同一账本重复记录。已创建分摊使用快照，不会回写、结清或删除原记账记录。

## 失败返回

通过 `window.onFailCallback(jsonString)`：

```json
{
  "action": "getLocalBills",
  "requestId": "bill-1",
  "data": {
    "code": "LOCAL_DB_ERROR",
    "msg": "读取本地账单失败"
  }
}
```

建议错误码：`INVALID_PARAMS`（参数错误）、`LOCAL_DB_ERROR`（数据库读取失败）、`UNSUPPORTED_ACTION`（当前版本不支持）。无需当前账本，不使用 `NO_ACTIVE_BOOK`。

H5 以 `action + requestId` 匹配响应，等待 10 秒；失败或超时显示重试入口，不注入模拟数据。用户关闭读取弹窗后的迟到响应不覆盖当前页面。未知、重复、错误 requestId 的回调被忽略。

## 最小验收

1. 所有账本合计 0、199、200、201 条支出分别返回 0、199、200、200 条。
2. 多个账本包含交错时间的消费时，跨账本统一返回最近 200 条，总数不超过 200；混合收入、转账、删除项时，先筛选再取数。
3. 切换当前打开的账本后，读取范围和结果不变（无账单变动时）；旧分摊快照保持原数据。不同账本相同消费 ID 不合并、不误判为重复。
4. 断开网络仍可读取；不触发业务请求或同步。
5. 名称含引号、中文或 HTML 字符时按文字展示；ID 稳定且不重复，金额按分计算。
6. 数据库失败走失败回调；旧客户端不支持时页面超时提示。
7. H5 勾选结清只修改分摊工具本地数据，不修改原支出。
